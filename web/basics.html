销量预测 · 零基础

一次手算，看懂销量预测

一条 28 天的小店数据，四种预测方法，误差从 25.7% 一路降到 0.5%。每一个数字你都能在手机上手算出来。

配合《销量预测工作台》阅读 · 真实基准数字来自 M4-Weekly / M4-Daily 本机复现

第 0 章 · 全局地图

所有预测算法，只在回答三个问题

不管叫 ARIMA 还是 Transformer，拆开看都只做三件事：

  1. 用哪一段过去？ 昨天的值、上周同一天、最近 4 周的平均、还是最近 100 步的全部？
  2. 怎么把它们组合成一个数？ 直接照抄、算平均、按指数加权、还是让模型自己学权重？
  3. 误差怎么量？ 决定了你往哪个方向优化。

你熟悉的数字电路里，一个功能可以由状态机硬写，也可以由查找表实现——输出一样，成本和适用场景不同。预测算法也是同一回事：没有最强的算法，只有匹配数据结构的算法。

下面每一节都是同一条数据、同一段预测窗口。你只需要盯着误差怎么变。
第 1 章 · 数据

先看清楚要预测的东西长什么样

某便利店每天卖出的矿泉水瓶数，我们有 4 周（28 天）历史，要预测第 5 周的 7 天。

把数据摊平成表，注意里面对角线的规律：

每一列是同一周的第 n 天。竖着看：周六那一列始终最高。横着看：每周整体比上周高一点点。

这里已经藏着两个结构 ① 周内节律（周期 = 7 天）　② 缓慢上升的趋势。后面所有方法，本质都是在用这两个结构的不同组合。
第 2 章 · 最笨的方法

Naive：把最后一个数复制 7 遍

ŷT+h = yT　　（h = 1, 2, …, 7）

最后一个观测是第 4 周的周日 = 166，所以下周七天全预测 166。

误差怎么量？用 WAPE（加权绝对百分比误差）：

WAPE = Σ|预测 − 实际| / Σ实际 = 246 / 958 = 25.7%
教训 ① 把"周日的 166"复制到"周一"，等于假装一周里没有节律。误差 25.7% 全是这么来的。预测的第一步不是选模型，是识别周期。
第 3 章 · 强得离谱的基线

SeasonalNaive：抄上周同一天

ŷT+h = yT+h−m　　（m = 周期 = 7）

要预测下周一，就看这周一；要预测下周六，就看这周六。

WAPE = 26 / 958 = 2.7%　　（从 25.7% 掉到 2.7%，只改了一行规则）
教训 ② 季节性是最强、最便宜的先验。任何模型如果打不过 SeasonalNaive，说明它什么也没学到。

这不是教学玩具。本工作台在 359 条真实周度销量上实测：SeasonalNaive 15.55%，LightGBM 8.07%。差距是真的，但起点也是真的高——所以专业流程永远是"先跑基线，再上模型"。

第 4 章 · 平滑

移动平均与指数平滑：把噪声磨掉，但会磨掉趋势

直觉：上周同一天只用了 1 个样本，太吵。那就把最近 4 周的同一天取平均。

ŷMon = (100 + 102 + 104 + 107) / 4 = 103.2

结果是 7.33%，比 SeasonalNaive 的 2.71% 更差。为什么？因为数据整体在涨，而 4 周平均天然滞后——它把趋势平均掉了。

ETS 的改进：不平权，越近权重越大

指数平滑（ETS 里的 S）不用等权平均，而是给最近的观测更大权重，按 α 衰减：

ŷt = α·yt−1 + (1−α)·ŷt−1　　（α = 0.6 时，权重是 0.6, 0.24, 0.096, …）

ETS 一共三个零件：Level（现在多高）、Trend（在涨还是在跌）、Season（周内形状）。AutoETS 的 model=ZZZ 就是让程序自动决定这三个零件开不开、怎么组合。

手工加回趋势项

既然趋势被抹掉了，就显式加回来：上周每周涨 29.7，平均到每天 +4.2。

ŷ = 上周同一天 + 4.2

WAPE = 5.2 / 958 = 0.54%。同一个模型结构，只是多了一个趋势项，误差降了 5 倍。

教训 ③ 先用眼睛找结构（周期、趋势），再让算法估参数。结构对了，参数粗糙也能赢；结构错了，参数再精也没用。
第 5 章 · 统计模型

ARIMA：把自己的过去当特征做回归

名字吓人，拆开只有三块：

字母含义在用哪部分过去
AR(p)自回归：用前 p 个值做线性回归yt−1, yt−2, …
I(d)差分 d 次，把趋势去掉变成平稳序列yt − yt−1
MA(q)用前 q 次"预测错了多少"来修正残差 et−1, …

AR(1) 写出来就是一条你非常熟的式子：

ŷt = c + φ·yt−1　　φ = 0.8 时：明天 ≈ 今天的 0.8 倍 + 常数

所以"自回归"没有任何玄学：它就是把 lag 当作 x 的线性回归，和后文 LightGBM 用的是同一批特征，只是拟合方式从"一条直线"换成"几百棵树"。

为什么 AutoARIMA 这么慢

AutoARIMA 不估参数，它穷举结构：p∈{0,1,2}、d∈{0,1}、q∈{0,1,2}，季节部分 (P,D,Q)7。

3 × 2 × 3 × 2 × 2 × 2 = 144 种组合 / 序列 ── 250 条序列 = 约 3.6 万次拟合

每一次拟合都要跑一遍参数估计和定阶检验。这就是今晚统计基线里最耗时的部分——不是它算得准，是它搜得久。

教训 ④ 统计模型适合结构清楚、序列不长、要可解释的场景（一条 SKU、一个门店）。你要是同时管 1000 条序列，穷举式搜索会成为工程瓶颈。
第 6 章 · 机器学习

LightGBM：换一种思路——把时间做成特征

到这里换思路：不写公式了，改把"时间"翻译成一张普通的表格，让机器学习。每一行 = 一个样本，每一列 = 一个特征。

真实数据构造出来的样本表。lag7 就是"上周同一天"——等于把 SeasonalNaive 的先验手工喂给模型；roll7_mean 是最近 7 天均值；dow 是星期几。

树在做什么

一棵树就是一堆 if-else：dow == 六 ? (lag7 > 150 ? 181 : 172) : …。它把样本分到叶子节点，叶子里的平均值就是预测。几百棵树各自看不同的特征组合，结果相加。

和 ARIMA 的根本区别在训练方式：ARIMA 逐条序列拟合自己的参数；LightGBM 把 359 条序列混在一起训练一个模型（所以叫"全局模型"）。它因此学到了跨序列的共性——"周六通常是工作日的 1.4 倍""节前一周会翘尾"，这对新上架、历史很短的 SKU 尤其有用。

多步预测的两种做法

  • 递归（recursive）：先预测第 1 天，把预测值当作已知，再预测第 2 天……误差会沿链条累积，越远越飘。
  • 直接（direct）：为第 1…13 周各训一个模型，谁都不依赖谁的预测值。更稳，但成本 ×h。

本工作台用的是递归 + 22 个特征。真实成绩：8.07%，SeasonalNaive 是 15.55%。 提升的大头不是"树很聪明"，而是 lag7 / rolling 这些特征把季节性显式喂了进去。

教训 ⑤ 树模型不自动理解时间。时间信息必须你亲手做成特征：lag、滑动窗口、星期几、节假日。特征工程 = 你对业务的理解的编码。
第 7 章 · 深度模型

五个模型，五种看曲线的角度

它们不是"更强的 LightGBM"，而是针对不同数据形态设计的五种归纳偏置（inductive bias）。理解它们，看"它假设曲线长什么样"就够了。

N-HiTS：退后看趋势，凑近看细节

把序列按不同尺度降采样：原始（看细节）、4 点平均（看周）、13 点平均（看季度）。每个尺度各出一份预测，再由粗到细叠加。

本工作台实测 8.88%，仅次于 LightGBM。

N-BEATSx：先把形状定义好，只学幅度

纯 MLP 堆叠，但每层输出被强制分解成趋势基函数和季节基函数的线性组合。数学上等于"我假设曲线 = 多项式趋势 + 傅里叶季节"，网络只学系数。

好处：可解释、参数少、训练快。实测 10.48%。

TFT：能说清"为什么"

三件武器：变量选择（自动判断哪个输入重要）、门控残差（决定信息怎么流）、注意力（决定看历史哪几段）。输入不限于销售历史，还能吃促销、天气、节假日。9.76%，但训练最慢（509 秒）。

什么时候选它：老板问"为什么这个门店下周会涨"，而你需要给出归因。

PatchTST：把序列切成块，像 ViT 切图

长序列如果用逐点注意力，计算量是 O(L²)；切成 patch 后 token 数大幅减少，且每个 patch 内部保留了局部形状。实测 8.49%（刚跑完，尚未并入榜单）。

DeepAR：不给你一个数，给你一片未来

它把预测变成一个似然函数（高斯 / 负二项 / 学生 t），训练目标就是最大化真实值的概率。缺点也在这里：采样带来方差，点预测（取中位数）往往不如判别式模型准，它的价值在区间和库存决策，不在排行榜名次。

第 8 章 · 指标

为什么用 WAPE，而不是 MAPE 或 RMSE

WAPE = Σ|预测 − 实际| / Σ|实际|
  • 它是加权的：卖 1000 瓶的店误差 50 瓶和卖 10 瓶的店误差 5 瓶，权重不同。这正是你想要的——总量视角。
  • 零值安全：MAPE 除以实际值，遇到 0 或接近 0 的销量会爆炸。WAPE 分母是总和，不会。
  • 可解释：8.07% 就是"预测的总量比实际总量偏了 8%"。

MASE 是"和 SeasonalNaive 比，你好了多少倍"：MASE < 1 表示比基线强，LightGBM 是 0.573，即误差只有基线的 57%。RMSE 会对大误差平方惩罚，适合"缺货罚得重"的场景，但不直观。

读任何一个排行榜之前先问三件事：数据集是什么、预测几步、指标怎么算。三个口径任何一个不同，名次就没有可比性。

第 9 章 · 进阶

那些"深坑"，等你把上面看懂再看

你现在看到的这份报告，另一半内容是踩坑记录。它们很重要，但属于第二阶段——先知道算法在干什么，再知道它会怎么坑你。

递归多步的误差累积（展开）
  • 递归预测时，第 2 步的输入是第 1 步的预测值，误差不是相加而是沿着链条放大。
  • 实战判断：13 周里前 3 步误差可控，后 5 步经常失真。解决办法是直接多步，或对远期单独建模。
时序数据不能随机切分（展开）
  • 随机 train/test 切分会让 lag 特征"看到未来"，离线指标虚高，上线就崩。
  • 正确做法：按时间切，训练段永远在测试段之前。
间歇需求、零膨胀与 log1p / Tweedie（展开）
  • 大量 0 的 SKU，用普通 L2 损失会预测出 0.3 这种无意义值。
  • 对策：log1p 目标变换、Tweedie / Poisson 损失，或用 Croston 这类间歇需求专用方法。
  • 本工作台的 LightGBM 会在验证集上自动挑 log1p 还是 Tweedie。
NaN、回退与口径不一致（展开）
  • AutoETS 在个别序列上拟合失败 → 预测为 NaN → 自动回退到 SeasonalNaive，必须在报告里标注，否则等于偷偷换了模型。
  • AutoARIMA 只跑了前 250 条序列，和 1000 条序列的模型不能 1:1 比较。
  • 2.4M 行长表一次性喂给 statsforecast 会让机器 swap，必须分块 + 缓存中间结果。
工程经验：先基线，再模型（展开）
  • 顺序：SeasonalNaive → 平滑/ETS → LightGBM（lag + rolling）→ 深度模型（需要区间或变量归因时）。
  • 每一层都要问："比上一层提升了多少？值不值这个工程成本？"
  • 这份报告的结论就是：359 条周度序列上，树模型 + 好特征赢过所有深度模型，而且训练时间差 1–2 个数量级。
