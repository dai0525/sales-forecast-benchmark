第 0 章

所有算法都在回答三个问题

  1. 用哪一段过去？昨天的值、上周同一天、最近 4 周的平均、还是最近 100 周的全部？
  2. 怎么组合成一个数？照抄、平均、指数加权、线性回归、还是几百棵树相加？
  3. 误差怎么量？决定了你往哪个方向优化。

类比：数字电路里同一功能可以用状态机写，也可以用查找表。输出一样，代价和适用场景不同。预测算法也是——没有最强，只有匹配数据结构。

第 1 章

数据与四种手算基线

某便利店 4 周（28 天）矿泉水销量，预测第 5 周 7 天。

竖着看周六那列始终最高（周内节律）；横着看每周比上周高一点（趋势）。

基线 1：Naive —— 把最后一个数复制 7 遍

ŷT+h = yT　→　166, 166, …, 166
WAPE = Σ|预测−实际| / Σ实际 = 246 / 958 = 25.7%

基线 2：SeasonalNaive —— 抄上周同一天

ŷT+h = yT+h−m　（m = 7）
WAPE = 26 / 958 = 2.7%　（只改了一条规则）
结论季节性是最强、最便宜的先验。真实数据上 SeasonalNaive 就有 15.55%——所以任何模型的第一道门槛是打赢它。
第 2 章

ETS / Theta：平滑、趋势与三个零件

移动平均为什么反而变差

ŷ周一 = (100+102+104+107)/4 = 103.2

WAPE 7.33%，比 SeasonalNaive 的 2.71% 更差。原因：数据在涨，4 周平均天然滞后，把趋势磨平了。

ETS：带遗忘的平均

ŷt = α·yt−1 + (1−α)·ŷt−1　（α=0.6 → 权重 0.6, 0.24, 0.096, 0.038 …）

Holt-Winters：三个方程各管一件事

水平 ℓt = α(yt − st−m) + (1−α)(ℓt−1 + bt−1)
趋势 bt = β(ℓt − ℓt−1) + (1−β)bt−1
季节 st = γ(yt − ℓt−1 − bt−1) + (1−γ)st−m
预测 ŷt+h = ℓt + h·bt + st+h−m·⌈h/m⌉

三个希腊字母就是三个旋钮：α 管水平多快跟上新数据，β 管趋势多快变，γ 管季节形状多快变。AutoETS(model="ZZZ") 里的 Z 就是“自动决定这三个零件开不开”。

手工加回趋势项

每周涨 29.7 → 每天 +4.24：

ŷ = 上周同一天 + 4.24

WAPE 0.54%。同一个结构，多一个趋势项，误差降了 5 倍。

Theta：M3 竞赛冠军（2000 年）的极简做法

把序列画成曲线，用 θ 参数控制“曲率”：θ=0 时曲线被拉直成一条趋势直线，θ=2 时就是原序列。

ŷt+h = SES(θ=0 直线段外推) + 季节因子 / 2

本质是“直线外推 + 半个季节修正”。它拿冠军说明一件事：结构简单的模型在短序列上极难被打败。

结论先用眼睛找结构（周期、趋势），再让算法估参数。结构对了，参数粗糙也能赢。
第 3 章

ARIMA：把自己的过去当特征做回归

字母含义用的历史
AR(p)自回归：前 p 个值做线性回归yt−1 … yt−p
I(d)差分 d 次，去掉趋势变平稳yt − yt−1
MA(q)用前 q 次预测残差修正et−1 … et−q
AR(1)：ŷt = c + φ·yt−1　（φ=0.8：明天 ≈ 今天×0.8 + 常数）

“自回归”没有玄学：就是把 lag 当 x 的线性回归。它和后面 LightGBM 用同一批特征，只是拟合方式从“一条直线”换成“几百棵树”。

为什么要差分：看这四周的总量

周总量差分
第 1 周843—
第 2 周874+31
第 3 周902+28
第 4 周932+30

原序列均值在漂移（不平稳），差分后稳定在 +30 左右（平稳）。ARIMA 的 I 就是把这个漂移先减掉，再对残差建模——否则回归系数会被趋势污染。

定阶靠 ACF / PACF 的形状

  • ACF（自相关函数）：在 lag 7、14、21 出现尖峰 → 有 7 周期结构，需要季节项。
  • PACF（偏自相关）：在 lag p 后截断 → AR 阶数取 p。

周期数据还要加季节项：ARIMA(p,d,q)(P,D,Q)m。周度数据 m=13（52 周 ÷ 4 季）或 52。

AutoARIMA 到底搜了多少

这里更正我之前说错的一句：statsforecast 的 AutoARIMA 不是穷举笛卡尔积，它默认 stepwise=True，用 Hyndman-Khandakar 逐步搜索，最多评估 94 个候选模型（nmodels=94）。若是全网格（p,q ≤ 5、P,Q ≤ 2、d ≤ 2、D ≤ 1），那才是约 1900 个组合。

即便如此，周度季节 ARIMA 每个候选都要拟合一次，实测 4 线程下约 2.6 秒/条序列，250 条就要 10 分钟量级——这就是它在今晚统计基线里最慢的原因。

结论统计模型适合结构清楚、序列短、要可解释的场景；几千条序列的批量预测，逐条拟合会成为工程瓶颈。
第 4 章

LightGBM 深挖：特征怎么来，树怎么修正误差

这一章回答两个具体问题：① 特征是怎么“提取”出来的？② 决策树是怎样一棵一棵把误差压下去的？

4.1 特征提取：把一条曲线变成一张表

树模型只看列，完全不知道“行与行的时间顺序”。所以时间信息必须手工编码成列。四步：

  1. 对齐时间轴：所有序列右对齐成同宽矩阵（短的左边补 NaN）。这样“往前第 k 天”就是“往左第 k 列”，取 lag 变成一个纯列位移。
  2. 造 lag 特征：把整列下移 1/7/14/28 行，得到 lag1、lag7、lag14、lag28。其中 lag7 就是“上周同一天”——等于把 SeasonalNaive 的先验手工喂给模型。
  3. 滚动窗口：对过去 7/14/28 列求 mean/std/min/max，得到 12 个特征，描述“最近的水平、波动、极值”。
  4. 日历特征：dow（星期几）、day、month、weekofyear、is_weekend，加上 series_id（哪条序列），拼成 22 维特征。

真实构造出来的样本行。lag1=昨天，lag7=上周同一天，roll7_mean=最近 7 天均值，标签 y=下一天销量。

4.2 一棵树能做什么：只会输出几个常数

在一棵深度 2、4 个叶子的树上，所有预测值只有 4 个可能：

用这 4 个常数去预测 7 天，得到 7 天里只有 4 个不同的数：122.3 / 127.7 / 141.9 / 138.5，WAPE 12.17%。这就是单棵树的偏差（bias）——它把问题粗分了几档就交卷了。

4.3 残差提升：每棵树只负责“上一轮没解释掉的部分”

Boosting 的规则只有两条：

残差 ri = yi − Fm−1(xi)　→　用第 m 棵树去拟合 r
Fm = Fm−1 + η · hm(x)　（η = 学习率，本实验 0.3）

把第 1 棵树留下的残差算出来（下表），第 2 棵树就是去学这些残差；第 3 棵学第 2 棵剩下的…… 每棵只走一小步（η 缩放），但方向一致。

周六：真实 183，1 棵树只给 141.9（残差 41.1）；60 棵树给到 176.5（残差 6.5）。残差就是下一棵树的训练目标。

4.4 为什么叫“梯度”提升

平方损失 L = ½(y−F)² 对 F 求导：∂L/∂F = −(y−F)。负梯度正好等于残差，所以“拟合残差”和“沿负梯度走一步”是同一件事。

换成 Tweedie / Poisson 损失时，“残差”的定义变了，但“沿负梯度走”不变——这就是 GBDT 能换损失函数的原因。LightGBM 还用二阶导（牛顿步）决定叶子里的输出值，所以收敛比一阶快。

残差是训练集上的残差；树多了会把训练残差压到 0，但测试误差反而上升——这就是 40/60 棵树变差的原因。

4.5 递归多步：误差是怎么被放大的

预测 13 周不可能一步给出，本工作台的做法是“预测一步 → 把预测值当作已知 → 再预测下一步”：

ŷt+1 → 填回 lag1 → ŷt+2 → … → ŷt+13

两个后果：

  • 误差沿链条复利：第 1 步的误差会成为第 2 步的输入特征。
  • lag7 从第 8 步起被污染：那之后“上周同一天”已经有一半是预测出来的。

替代方案是直接多步：为第 1…13 周各训一个模型，互不依赖，代价是训练成本 ×13。

参数本工作台管什么

learning_rate0.05每棵树的分量，越小越稳但需要更多树

目标变换在验证集上选：log1p 的 WAPE 3.06% vs Tweedie 3.11%，选了 log1p。测试集结果 3.78%（1000 条日度序列，预测 14 天）。

结论树模型不自动懂时间。lag7 这类特征是“你对业务的理解”的编码；提升树负责在这张表上做加法修正。特征决定上限，树数决定逼近上限的程度。
第 5 章

五个深度模型：输入、算子、输出

共同外壳：每条序列除以自身均值做归一化 → 输入最近 100 周 → 网络 → 输出 13 周 → 乘回均值。损失用 L1（DeepAR 用似然）。

N-HiTS：多速率采样 + 分层插值

ŷ = Σk interp( MLPk( avgpoolrk(x) ) ),　rk ∈ {1, 2, 4}

每个 block 先把输入按 r 倍平均池化（相当于“退后看”），过 MLP，再上采样回原长度，作为残差从输入里减掉传给下一个 block。粗尺度抓大形状，细尺度补细节。

实测：周度 8.88%，参数量 321.4K。

N-BEATSx：把基函数写死，只学系数

forecast = Σi θif · bi(t),　bi = 多项式基 或 傅里叶基

每层同时输出 backcast（解释掉的部分）和 forecast（预测）。因为基函数是显式写好的（趋势多项式、季节傅里叶），网络只需要学系数 θ——参数少、可解释、训练快。周度 10.48%，参数量 500.2K。

TFT：变量选择 + 注意力 + 分位数

输入分三类：静态特征（门店属性）、已知未来（节假日、促销计划）、仅历史（销量）。三步：

  1. VSN 变量选择：v = softmax(MLP(x)) ⊙ x，给每个输入一个可学习权重，不重要的自动压到 0。
  2. LSTM 编码 + 可解释注意力：注意力权重直接告诉你“这次预测主要看历史哪几段”。
  3. 分位数输出：一次输出 P10/P50/P90，用分位数损失训练。

周度 9.76%，参数只有 38.9K，但训练最慢（509 秒）——注意力序列长度是瓶颈。

PatchTST：把序列切成 token

逐点注意力的复杂度是 O(L²)；切成 patch 后 token 数变成 L/P，同时 patch 内部仍保留局部波形。再加上通道独立（每条序列单独过网络、共享权重），避免不同序列互相干扰。周度 8.49%（刚跑完，尚未并入榜单），参数量 78.6K。

DeepAR：输出分布，而不是一个点

p(yt | ht) = N(μ(ht), σ(ht))　或　负二项(μ, α)

训练时用 teacher forcing（下一步输入喂真实值）；预测时自回归采样：从分布里抽一个值 → 喂回网络 → 再抽下一个点，重复几百次得到一条路径，几百条路径就是区间。

代价：采样有方差，点预测（中位数）常不如判别式模型准。它的价值在库存决策与风险，不在排行榜名次。

第 6 章

BSTS：贝叶斯结构时序，到底在做什么

你看到的“概率学时间序列”，代表就是 BSTS（Bayesian Structural Time Series）。它不是一个新模型，而是一个状态空间模型 + 一套贝叶斯推断。

6.1 模型：把曲线拆成几个隐状态

观测：yt = μt + γt + βTxt + εt,　εt ~ N(0, σ2obs)
水平：μt+1 = μt + δt + ηt　（局部线性趋势）
季节：γt+1 = −Σj=1..m−1 γt+1−j + ωt

写成矩阵就是标准状态空间：αt+1 = Tαt + Rηt，yt = Zαt + εt。状态 α 里装着“现在的水平、斜率、m 个季节偏移”。

和 ETS 的区别：ETS 是这套方程的一个特例；BSTS 多了 βTxt（外生变量，如促销、天气）和完整的不确定性传播。

6.2 卡尔曼滤波：先预测，再按证据修正

这一步你在控制里见过。给定先验 N(100, 20²)，来了一个观测 110（观测噪声 σ=10），后验是两者按信息量加权：

K = σ2prior / (σ2prior + σ2obs) = 400/500 = 0.8
μpost = 100 + 0.8 × (110 − 100) = 108　　σ2post = (1−K)·400 = 80 → σ ≈ 8.94

整条序列就是这么滚动：t 时刻预测 → 观测到 yt → 用 K 修正 → 进入 t+1。缺失值可以跳过修正（只用预测），所以 BSTS 对缺数据非常友好。

6.3 贝叶斯层：先验 + MCMC

BSTS 在卡尔曼之外加了三样东西：

  1. 先验：各层方差用逆伽马先验；回归系数用 spike-and-slab（每个系数有一定概率精确为 0），这就是自动变量选择。
  2. 后验采样（Gibbs）：交替做两件事——给定方差，用模拟平滑器抽状态路径；给定状态路径，从共轭后验抽方差。迭代几千次。
  3. 后验预测：每条抽样路径往后推，得到一整族未来 → 分位数就是可信区间（credible interval，“参数落在这里的概率 90%”，比频率派置信区间更符合直觉）。

副产品：把干预后那段“反事实”路径抽出来减掉实际值，就是 CausalImpact 的做法——本质是 BSTS 加反事实推断。

6.4 我在你的周度数据上真跑了

环境里没有 MCMC 库（orbit/pymc 都没装），所以用 statsmodels 的 UnobservedComponents 跑了同一个状态空间模型的极大似然版：局部水平 + 随机季节(52) + 观测噪声，卡尔曼滤波 + L-BFGS。这样测的是“结构值多少”，不含先验带来的差异。

M4-Weekly，最后 13 周为测试，同一批 359 条序列。SN(m=52) 与榜单上的 15.55% 完全吻合，说明口径一致（逐序列 WAPE 再取均值）。

两个反直觉的结论：

  1. 季节周期选错，代价极大：同样 359 条序列、同样是局部水平 + 随机季节，m=13 是 8.79%，m=52 是 7.84%——1 个百分点白送。子集上更夸张：60 条时 14.47% → 9.61%。周度数据的一年是 52 周，13 周只是季度——周期就是模型的先验，选错等于先验错了。
  2. 点预测上 BSTS 略胜 LightGBM：7.84% vs 8.07%。它没有任何跨序列学习，只靠“把每条序列拆成水平 + 年周期 + 噪声”，但 M4-Weekly 的季节性太强，结构对了就够了。

结构选择的影响（m=13、40 条子集的对比）：局部水平 18.38%、局部线性趋势 19.02%、平滑趋势 23.83%、确定性季节 19.21%——加趋势项反而更差，因为随机游走的斜率外推 13 周会把噪声当趋势。所以 BSTS 的“调参”其实只有两件事：要不要趋势、季节周期取多少。

6.5 它适合什么，不适合什么

适合不适合
数据量单序列短历史（几十到几百点）成千上万条序列
需求要分解、要区间、要外生变量归因只需要跨 SKU 的批量点预测（用 LightGBM 更省）
缺失值天然支持—
成本单条约 0.75 秒（359 条 268 秒/3 进程）上万条序列要逐条拟合；MCMC 版再慢一个量级
判断在你这份周度数据上，BSTS 不是“只能看区间”的配角——点预测 7.84% 甚至略好于 LightGBM 的 8.07%。但做批量生产我仍选 LightGBM，三个理由：跨序列共享（新上架 SKU 冷启动靠别的序列）、成本线性（逐条拟合，10 万条就是 20 小时量级）、特征显式（促销、节假日想加就加）。BSTS 留给三种场景：单品类深挖、活动增量归因（CausalImpact）、给业务解释“为什么这么预测”。
第 7 章

指标：为什么是 WAPE

WAPE = Σ|预测 − 实际| / Σ|实际|
  • 加权：卖 1000 瓶的店误差 50 瓶，和卖 10 瓶的店误差 5 瓶，权重不同。
  • 零值安全：MAPE 除以实际值，遇到 0 会爆炸；WAPE 分母是总量。
  • 可解释：8.07% 就是“预测总量比实际总量偏了 8%”。

MASE 是“相对 SeasonalNaive 的倍数”：LightGBM 周度 MASE 0.573，即误差只有基线的 57%。RMSE 重罚大误差，适合缺货成本高的场景。

读榜前先确认三件事：数据集、预测步长、指标口径。任何一项不同，名次都不可比。

M4-Weekly，359 条序列，预测 13 周，同一套切分与指标（逐序列 WAPE 取均值）。BSTS 一行为极大似然版结构模型，不含 MCMC 先验。

递归多步的误差累积（展开）
  • 第 2 步的输入是第 1 步的预测值，误差沿链条放大，不是相加。
  • 13 周里前 3 步通常可控，后 5 步开始失真。
  • 对策：直接多步（每步一个模型），或对远期单独建模。
时序不能随机切分（展开）
  • 随机切分会让 lag 特征“看到未来”，离线指标虚高，上线就崩。
  • 训练段必须永远在测试段之前；验证集也要按时间滚动。
间歇需求与零膨胀（展开）
  • 大量 0 的 SKU，用 L2 会预测出 0.3 这种无意义值。
  • 对策：log1p、Tweedie/Poisson 损失，或 Croston 类方法。
NaN 回退与口径不一致（展开）
  • 个别序列拟合失败 → NaN → 回退 SeasonalNaive，必须在报告里标注。
  • AutoARIMA 只跑子集、深度模型只跑 300 条，和全量模型不能 1:1 比。
  • 2.4M 行长表一次性喂给 statsforecast 会 swap，必须分块 + 缓存。
工程顺序：先基线，再模型（展开）
  • SeasonalNaive → ETS/Theta → LightGBM（lag + rolling）→ 深度模型 → BSTS（需要解释/区间时）。
  • 每一层都问：比上一层提升多少？值不值这个工程成本？
  • 本工作台结论：359 条周度序列上，树模型 + 好特征赢过所有深度模型，训练时间差 1–2 个数量级。
